이 스킬은 이 프로젝트의 이슈/티켓 관리 절차를 정의한다. 아래 규칙에 따라 티켓을 만들고 상태를 관리한다.

## 티켓 만들 때
- 제목: 동사로 시작하는 한 줄 요약 (예: "로그인 실패 시 에러 토스트 노출").
- 본문: **배경 / 할 일 / 완료 조건(AC)** 3단 구성.
- 적절한 타입(Story/Task/Bug), 우선순위, 담당자, 라벨을 지정한다.

## 상태 전환
- 작업 시작 시 `In Progress`로 옮기고, 자기 자신을 담당자로 지정한다.
- PR 올리면 `In Review`, 머지되면 `Done`으로 옮긴다.
- 막히면 상태를 그대로 두고 코멘트로 블로커를 남긴다.

## 코드와 티켓 연결
- 브랜치명에 티켓 키를 넣는다: `feature/PROJ-123-short-desc`.
- 커밋 메시지 첫 줄에 티켓 키를 넣는다: `PROJ-123: 로그인 에러 토스트 추가`.
- PR 설명에 `Closes PROJ-123`처럼 티켓을 링크한다.
