# {{회사·서비스명}} 지식 베이스 규칙 (v0.1)

> 한 문장: **원본은 추가만 하고, 페이지는 원본을 가리키며, 확정은 {{결정권자}}만 찍고, 검사는 코드가 한다.**

이 파일이 규칙의 정본이다. 사람만 고친다. 에이전트는 PR로 개정을 제안만 한다.

---

## 1. 층 — 누가 쓰나로 나뉜다

```
schema/        규칙·타입·영역          사람만 쓴다 (에이전트는 PR 제안)
raw/           원본 (텍스트 추출본)     추가만. 수정·삭제 금지
wiki/{영역}/    페이지                  areas.md에 선언된 영역
index.md       목차·확정 대기           스크립트가 생성
```

페이지는 **`wiki/<영역>/` 아래에만** 산다. 영역 목록의 정본은 [areas.md](areas.md)다. 루트에는 페이지가 아닌 것(`schema/`·`raw/`·`state/`·작업 공간)만 둔다 — `wiki/` 밖의 `.md`는 페이지가 아니다.

**`raw/`를 추가만 하는 이유**: 페이지의 모든 문장이 `raw/`를 가리킨다. 원본이 바뀌면 출처 표기가 거짓이 된다. 페이지가 틀렸을 때 되돌아갈 바닥은 `raw/` 하나뿐이다.

`raw/` 하위: {{확보된 원천 목록 — 예: confirmations/(결정권자 확인 원문) · github/ · ops/ · external/}}

원본 바이너리(pdf·docx·이미지)는 넣지 않는다. 텍스트만 둔다. 개인정보는 **적재 단계에서** 가린다.

## 2. 무엇이 여기 오나 — 라우팅

판정 질문 둘, 순서대로:

1. **코드를 다시 읽으면 확인되는 사실인가?** → `{{코드맥락 저장소 — 예: context/}}`
2. **사람이 정했거나 밖에서 온 사실인가?** → 이 지식 베이스 (+ 출처 표기)

코드 맥락은 원천이 코드 자체라 출처·등급이 의미가 없다(언제든 다시 읽어 확인 가능). {{결정권자}} 결정·도메인 정의·운영 수치는 **원본이 사라지면 확인할 길이 없어서** 출처와 등급이 반드시 필요하다. 그 차이가 경계다.

{{기존 자산 처리 — 예: study/(일반 지식) · decision-log/ · 각 repo 코드위키는 건드리지 않는다. 기존 N개는 이관하지 않는다.}}

## 3. 사실 3등급

| 등급 | 근거 | 본문 표기 |
|---|---|---|
| **확정** | {{확정 입구 — 예: 결정권자의 확인 원문, 또는 결정권자가 승인한 PR}} | `[확인:{{결정권자}} YYYY-MM-DD]` |
| **문서상** | 초안·외부 자료·DB 조회·내 관찰. 확인 없음 | `[src:n]` |
| **추론** | 근거 없음 | `[추론]` |

- `[src:n]`의 `n`은 그 페이지 `sources` 목록의 순번(1부터).
- **에이전트와 작업자는 스스로 확정을 올리지 못한다.** 올리는 길은 위 표의 입구뿐이다. 원문은 **요약하지 않고 그대로** 적재한다.
- **확정만 허용하는 상태값**: {{예: `decision: decided`, `spec: active`}}. 근거가 없으면 초안 상태로 두고 `confirm_pending: true`를 붙인다.
- **등급을 낮추는 것과 사실을 빼는 것은 다르다.** 두 원본이 숫자를 다르게 적었으면 **둘 다 적고** 등급을 낮춘 뒤 `question` 페이지를 만든다. 하나를 고르지 않는다.

### 충돌 우선순위

1. 더 최신의 {{결정권자}} 확인 원문 → 2. {{공식 기록 — 그 업종의 체결·승인 문서}} → 3. 더 최신의 회의록·결정 → 4. 계획·제안 문서(버전 높은 쪽) → 5. 대화·채팅

같은 단계면 최신이 이긴다. 진 쪽은 **지우지 않고** 본문 `## 이력` 절로 내리고, 이긴 쪽 `supersedes`에 적는다.

## 4. 페이지

### 프론트매터 — 사람 6칸 + 자동 3칸

```yaml
---
type: decision
title: {{제목}}
status: decided
area: {{영역}}
sources: [raw/confirmations/YYYY-MM-DD-....md]
updated: YYYY-MM-DD
# ── 조건부
confirmed_by: {{결정권자}}
confirmed_at: YYYY-MM-DD
confirm_pending: true          # 확정 대기 중 (린트가 조르지 않게)
supersedes: []
# ── 스크립트가 채움 (사람·에이전트가 쓰지 않는다)
id: dec-0003
created: YYYY-MM-DD
grade_marks: 확인 1 · 출처 2 · 추론 0
---
```

계산할 수 있는 칸은 스크립트가 채운다. `sources`가 비면 페이지를 만들 수 없다 — `question`만 예외.

### 본문

- 다른 페이지 참조는 `[[wiki/영역/파일명]]` 으로만(repo 루트 기준). URL·상대경로 금지.
- 날짜는 `YYYY-MM-DD`. 숫자는 **원본 표기와 단위를 유지**한다.
- 페이지 1,500자 안팎. 넘으면 하위 페이지로 나눈다.
- 타입별 필수 절은 §5.
- 변경 경위는 커밋 메시지에 남긴다. **등급·숫자·상태가 뒤집힌 경우**에만 본문에 `## 이력` 한 줄을 추가한다.

## 5. 타입

| 타입 | id | 허용 상태값 (**굵게** = 끝) | 확정만 허용 | 필수 절 |
|---|---|---|---|---|
| `decision` | `dec-` | proposed · **decided** · **reversed** | `decided` | 결정 / 이유 / 버린 대안 |
| `question` | `q-` | open · **answered** · **closed** | — | 질문 / 왜 열렸나 / 지금까지 나온 것 |
| `concept` | `c-` | active · **retired** | — | 정의 / 계산·판정 기준 / 주의 |
| `spec` | `s-` | draft · active · **superseded** | `active` | 한 줄 요약 / 지금 어떻게 동작하나 / 규칙 / 예외 |
| `event` | `e-` | open · in-progress · **closed** · **cancelled** | — | 무슨 일 / 경과 / 남은 것 |

{{이 회사에서 가장 오래 사는 타입과 그 이유를 한 줄 — 예: concept(용어·계산식)이 핵심 자산이다}}

- 기계 판독 규격은 [types.json](types.json). **두 벌의 상태값이 갈라지면 린트가 실패한다.**
- 타입을 늘리는 기준: 맞는 타입이 없는 페이지가 **같은 성격으로 3건** 모이면 신설을 제안하고 {{결정권자}} 승인(PR)으로 확정한다. 그전엔 `event`로 둔다.

## 6. 운전

| 하는 일 | 누가 | 언제 |
|---|---|---|
| 적재 ({{원천}} → `raw/`) | {{누가}} | {{언제}} |
| 컴파일 (원본이 건드리는 페이지 갱신·충돌 해소) | {{누가}} | 적재 직후 |
| 자동 칸 채우기 | 스크립트 | 커밋 직전 |
| 규격 검사 (린트) | 스크립트 | {{주기}} + PR |
| 확정 | **{{결정권자}}** | {{확정 자리}} |

**모든 작업의 첫 단계**: `index.md`와 이 규칙을 읽는다 → 작업 → 자동 칸 → 커밋.
**지식 베이스 먼저**: 답하기 전에 읽는다. 없으면 *"지식 베이스에 없음"* 이라고 말한 뒤에만 추론한다.

### 린트가 보는 것

1. `sources`에 적힌 파일이 실제로 있나
2. `[[링크]]` 대상이 실제로 있나
3. 필수 칸이 있나 / `status`가 허용값인가 / `area`가 `areas.md`에 있고 `wiki/<area>/` 폴더와 같은가 / `id` 중복
4. `[src:n]`의 `n`이 `sources` 범위 안인가
5. **확정만 허용하는 상태값인데 확정 근거가 없나** — `confirm_pending: true`면 넘어간다

결과는 `index.md`의 **「확정 대기」** 절로 모인다. 선언만 되고 빈 영역은 공백으로 올리지 않는다.
