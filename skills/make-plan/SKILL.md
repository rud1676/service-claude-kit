# 계획·설계 문서 작성 표준 (공용)

> 출발점: 글·코드 위주 설계서는 읽기 힘들다 → **화면을 먼저 보여주고 "이걸 만들려고 이렇게 설계했다"** 로 읽히게 바꿨더니 바로 이해됐다.
> **골드 샘플**: 프로젝트에 이 형식으로 잘 쓴 문서가 생기면 맨 아래 `프로젝트 커스터마이징`에 경로를 적어 둔다. 형식이 애매하면 그 문서를 Read 해서 따라 한다.

## 역할 분담

| 이 스킬이 정하는 것 | 호출 스킬이 정하는 것 |
|---|---|
| 문서 골격 순서(요약 → 메타 → §0 화면 → 그림 → 결정 → 상세 → 배포·테스트·리스크) | 상세 섹션의 **내용**(범위·사실 확인·파일 표·STEP·검증 시나리오) |
| 화면 재료 확보 절차(찾기 → Figma → 개발서버 캡처 → 요청) | 저장 경로·파일명(예: `./plan/{도메인}-{기능}-plan.md`) |
| 시각화 규칙(mermaid·표·접기·강조 박스·예시 그림) | 승인 문구·승인 후 다음 단계 |
| 셀프 체크리스트 | 임시 문서 여부(완료 후 `plan/complete/` 로 이동) |

상위 스킬의 스켈레톤 섹션은 **빼지 않고** 이 골격의 "상세" 자리에 그대로 넣는다. 번호는 다시 매겨도 된다.

---

## 0. 호출 계약

```
Skill({ skill: 'make-plan', args: `
문서: plan | design            # plan = 작업용(완료 후 plan/complete/ 로 이동), design = 남는 설계 문서
저장 경로: <상위 스킬이 정한 경로>
화면: 있음 | 없음              # API·배치·마이그레이션만이면 없음
화면 재료: <Figma 링크 / 캡처 png 경로 / 기획 문서 경로 / 없음>
본문 스켈레톤: <상위 스킬의 섹션 목록 또는 "상위 스킬 SKILL.md 의 plan 스켈레톤">
내용: <취조·분석 결과 요약>
` })
```

명시 호출(`/make-plan`)이면 위 항목을 대화에서 모으고, 모자란 것만 묻는다.

---

## 1. 화면 재료 확보 (화면: 있음 일 때만)

순서대로 시도하고, 찾은 단계에서 멈춘다.

1. **기존 캡처 찾기** — 기획 문서 옆 `assets/`, 기획 문서 본문의 `![](...)` 를 grep 한다. 찾으면 Read 로 **직접 열어 보고** 어떤 화면인지 확인한 뒤 쓴다(파일명만 보고 쓰지 않는다).
2. **Figma 링크가 있으면** — `get_screenshot` 으로 화면을 확인한다. 파일로 저장할 수 있으면 아래 위치에 저장하고, 저장이 안 되면 문서에 Figma 링크 + 화면 설명을 남긴다. 화면 구조·컴포넌트 매핑이 필요하면 [`figma-depth-find`](../figma-depth-find/SKILL.md) 를 쓴다.
3. **이미 배포된 화면이면 개발서버에서 직접 캡처한다** — Playwright headless 로 로그인해 해당 화면을 찍는다(AS-IS 캡처용). URL·계정은 `프로젝트 커스터마이징` 값을 쓴다.
   - 계정 비밀번호는 문서·스크립트에 하드코딩하지 않고 환경변수(예: `PLAN_CAPTURE_PW`)로 받는다. 값이 없으면 사용자에게 묻는다.
   - 팁: 모바일 화면이면 viewport 430×900, `locale: 'ko-KR'`. 로그인 성공은 토큰 저장(쿠키/localStorage) 여부로 판단하고, 이후 `page.goto(BASE + '/<경로>')`. 스크립트는 playwright 의존성이 있는 프론트 레포에서 실행한 뒤 삭제한다.
   - 화면 캡처와 함께 그 화면이 쏘는 네트워크 요청(`page.on('response')`)도 같이 떠 두면 "AS-IS 동작" 근거가 된다.
4. **그래도 없으면 사용자에게 요청한다** — 추측으로 화면을 묘사하지 않는다.
   > "이 작업은 ○○ 화면이 바뀝니다. AS-IS/TO-BE 캡처(png 경로)나 Figma 링크를 주시면 §0 에 넣겠습니다. 없으면 텍스트 와이어프레임으로 대신합니다."
   - 사용자가 "없다/그냥 진행"이면 **텍스트 와이어프레임**(코드블록 박스 그림)으로 §0 을 채운다.

**이미지 저장 위치**
- `문서: design` → 기획 문서의 `assets/` 를 재사용(새 캡처도 같은 곳, `NN-설명.png`).
- `문서: plan` → `./plan/assets/<plan 파일명>/`. plan 을 `plan/complete/` 로 옮길 때 `plan/complete/assets/` 로 **같이 옮긴다**.
- 경로는 문서 기준 **상대 경로**로 건다.

## 2. 문서 골격

```markdown
# [계획|설계] <제목>

> **한 줄 요약** — 이 작업이 끝나면 화면/동작이 어떻게 달라지나(사용자 관점 1~2문장).
> (plan 이면) ⚠️ **임시 문서**: 작업 중에만 사용. 완료 후 `plan/complete/` 로 이동.

| 상태 | 기획 | 연결 문서 | 기준 코드 |
|---|---|---|---|

---

## 0. 무엇을 만들기 위한 계획인가 — 화면으로 보기
  - 문제(AS-IS) 캡처 + 2~4줄 설명
  - 목표(TO-BE) 캡처를 <table> 로 나란히, 각 칸 아래 "여기서 바뀌는 것" 불릿
  - 화면 ↔ 설계 연결표 | 화면에서 보이는 것 | 그걸 만드는 설계 | 위치(§링크) |
  (화면 없는 작업: "0. 무엇이 달라지나" — 요청/응답 예시나 데이터 전후 비교로 대신)

## 1. 전체 그림
  - mermaid(flowchart / sequenceDiagram) 1개 + 레포별 변경 표
  - 역할·등급별로 동작이 갈리면 매트릭스 표

## 2. 설계 결정            | # | 결정 | 왜 |   (PRD/기획에 없던 결정만)

## 3~N. 상세               ← 상위 스킬 스켈레톤 섹션을 여기에 그대로

## 배포·롤백               mermaid 순서 + "섞인 상태" 표 (해당 없으면 생략)
## 테스트                  표(케이스 | 기대) 또는 - [ ] 체크리스트
## 남은 리스크·열린 이슈    표(리스크 | 대응)
```

상위 스킬 스켈레톤에 이미 "리스크/주의"·"작업 순서(STEP)" 가 있으면 중복 섹션을 만들지 말고 그 섹션을 이 골격 자리에 둔다.

## 3. 시각화 규칙

| 이런 내용이면 | 이렇게 |
|---|---|
| 요청 흐름, 레포 간 호출, 배포 순서 | **mermaid** `flowchart LR` / `sequenceDiagram` (노드 줄바꿈은 `<br/>`) |
| 조건에 따라 결과가 갈림(권한×상태, 성공/실패 경우의 수) | **표** — 행 = 경우, 열 = 결과 |
| 집합·공식·병합 규칙 | 코드블록 안 **예시 그림**(실제 값으로 한 줄씩 계산) |
| 화면 여러 개 비교(A/B/C, AS-IS/TO-BE) | `<table>` 에 이미지 나란히 + 칸 아래 설명 |
| 15줄 넘는 코드 | `<details><summary><b>코드 — 이름</b></summary>` 로 접고, 본문엔 그 코드가 하는 일을 표로 요약 |
| 놓치면 사고 나는 함정·순서 제약 | `> [!WARNING]` / `> [!IMPORTANT]` / `> [!CAUTION]` (남발 금지, 문서당 3개 안쪽) |
| 해야 할 확인 | `- [ ]` 체크리스트 |
| 신규/보류/금지 표시 | 🆕 ✅ ⏳ ⛔ 정도만 |

- 문장은 짧게. 한 셀·한 불릿에 사실 하나.
- 파일 경로·라인은 상세 섹션과 표에만. §0·§1 은 사용자 관점 언어로.
- 렌더 호환: GitHub 기준으로 쓴다. 사용자가 Obsidian 에서 본다고 하면 `<details>` 를 풀고 일반 코드블록으로 바꾼다(Obsidian 은 HTML 블록 안 마크다운을 안 그림).

---

## 4. 셀프 체크 (출력 전)

- [ ] 첫 화면(요약 + §0)만 읽어도 "무엇을 만들려는지" 알 수 있다
- [ ] 화면 있는 작업인데 §0 에 캡처도 와이어프레임도 없는 상태가 아니다 (없으면 1단계 4번 요청을 했다)
- [ ] 이미지 경로가 실제로 존재한다(`ls` 로 확인)
- [ ] mermaid 가 문법상 닫혀 있다(`end`, 따옴표, `<br/>`)
- [ ] 상위 스킬 스켈레톤의 섹션이 빠짐없이 들어갔다
- [ ] 앵커 링크(§ 이동)가 실제 헤딩 슬러그와 맞는다
- [ ] 계정 비밀번호·토큰 같은 비밀값이 문서에 들어가지 않았다

## 5. 마무리

문서를 저장하고 경로를 알린 뒤 **상위 스킬로 돌아간다**(승인 문구·대기는 상위 스킬 몫). 명시 호출이면 "검토해주세요"로 멈춘다.
