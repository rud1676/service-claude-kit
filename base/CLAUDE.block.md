## 워크스페이스 구조

이 폴더는 **작업 워크스페이스**다(그 자체는 git 저장소가 아니다). 실제 코드 git 작업은 `repository/` 안의 각 repo에서 한다.

| 폴더 | 용도 | git |
|---|---|---|
| `wiki/` | 프로젝트 지식 위키 — 코드만 봐선 알 수 없는 맥락(분석·결정·기획·동작원리). `explain` 스킬이 관리 | 워크스페이스는 비-git |
| `study/` | **내** 학습 기록 — "이거 어떻게 동작해?"처럼 내가 몰라서 물어본 것. wiki와 완전 분리(서로 승격 안 함) | 〃 |
| `decision-log/` | 결정의 갈림길 아카이브 — **미결/확정** 결정을 사유·버린 대안과 함께. wiki와 상호 링크 | 〃 |
| `plan/` | 큰 작업의 임시 맥락. 작업 끝나면 삭제 | 〃 |
| `claude-log/` | 세션 추적 로그(훅이 자동 생성). 사람이 직접 안 씀 | 〃 |
| `repository/` | 실제 코드 repo들(front·server 등). 각각 독립 git repo. 워크트리는 `repository/{repo}-worktree/{작업번호}/` | 각 repo가 git |

## wiki (프로젝트 지식)

- 위치: `./wiki/{도메인}/*.md`. 도메인별 주제 문서를 둔다. (예: `./wiki/auth/token-refresh.md`)
- 인덱스: `./wiki/README.md` 가 전체 목차. 새 문서를 만들면 여기 표에 한 줄 설명을 추가/갱신한다.
- 용어 정의는 `./wiki/{도메인}/terminology.md` 에 "무슨 뜻인가" 개념 위주로.
- **갱신 규칙**: 대화 중 확정된 사실·결정·기획 변경이 드러나면 해당 파일에 반영하고(없으면 생성) 답변 말미에 한 줄로 알린다. **덮어쓰기 금지** — 충돌하면 갱신/추가, 번복됐으면 `## 후속 (날짜)`. 모든 주장엔 `파일:줄` 근거 + 상단에 작성 날짜·대상 커밋. 잡담·임시 판단은 기록하지 않는다.
- 문서 생성·정리는 `explain` 스킬이 담당한다.

## study (내 학습)

- 내가 "이 함수/개념 어떻게 동작해?"라고 물어 이해한 내용을 `./study/` 에 남긴다. wiki(프로젝트 진실)와 목적이 다르므로 **섞지 않는다.**
- 학습 질문에 답한 뒤, 이후에도 참고할 값진 내용이면 "`./study/`에 정리할까요?"라고 물어보고 승인 시 저장한다. 그 자리서 끝날 질문은 저장하지 않는다.

## decision-log (결정 아카이브)

- 판단이 갈렸거나 대안을 버린 결정을 `./decision-log/<YYYY-MM-DD>-<주제>.md` 에 append-only로 남긴다. "무엇을 택했고 어떤 대안을 왜 버렸나 / 아직 미결이면 왜 미결인가"가 핵심.
- 상태(미결/확정)를 표기하고 wiki 문서와 상호 링크한다. 매번 남기지 말 것 — 판단이 갈렸을 때만.

## claude-log (세션 추적 로그)

- **읽기/요약 같은 추적 메타는 사용자에게 보이는 답변 본문에 절대 출력하지 않는다.** 전부 `./claude-log/<session_id>.md` 세션 파일에만 남긴다. (아래는 설치된 훅이 실제 수행하는 동작)
  - 읽기 기록: `log-read.py`(PostToolUse) 훅이 모든 Read/Grep/Glob 호출을 세션 파일 표에 자동 적재한다. 내가 따로 적을 필요 없음.
  - 능동 참고: 그 턴에 능동적으로 참고한 비-소스 문서(`*.md`·규칙·`./wiki/**`·`terminology.md` 등)가 있으면, 답변 맨 끝에 안 보이는 HTML 주석으로 `<!-- 📖 read: <파일> — <이유> -->` 한 줄씩 남긴다(소스코드 탐색 제외, 없으면 생략). Stop 훅이 세션 파일 끝 `## 능동 참고 문서` 섹션에 누적한다.
  - 세션 요약: 기록할 만한 실제 작업이 있었던 응답에서만, 답변 맨 끝 줄에 렌더링 안 되는 HTML 주석으로 `<!-- 📝 요약: <핵심 한 문장> -->` 만 남긴다. 잡담·되묻기·단순 확인 턴은 생략. Stop 훅이 세션 파일 헤더 `- 요약:` 에 갱신(요약이 한 번도 없으면 첫 사용자 요청으로 시드).
  - 토큰 사용량: Stop 훅(`summarize-session.py`)이 매 응답 끝에 메인 transcript의 assistant `usage`를 합산해 헤더 `- 토큰: …` 한 줄로 갱신한다. 내가 따로 적을 필요 없음.
  - 탐색 집계: 같은 Stop 훅이 메인 transcript + `<session>/subagents/*.jsonl` 를 훑어 실제 탐색량(Read/Grep/Glob + Bash grep·find·ls 등)을 재계산해, 헤더 `- 탐색: …` 한 줄과 파일 끝 `## 탐색 집계` 섹션(서브에이전트별 표)으로 매 턴 덮어쓴다(누적 아님). log-read 표는 메인 Read만 잡으므로 실제 탐색량은 이 섹션으로 본다.

## git (repository/)

- `repository/` 하위 각 repo는 독립 git이므로 브랜치·커밋은 반드시 해당 repo 폴더 안에서 실행한다.
- 한 repo에서 독립 작업 여럿을 동시에 하면 브랜치 전환 대신 워크트리를 `repository/{repo}-worktree/{작업번호}/` 로 만들어 병렬 처리한다.
- 커밋·PR은 사용자가 명시적으로 요청할 때만 수행한다. 코드 검토는 PR에서 사용자가 한다.
